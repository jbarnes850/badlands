# Citation-grade Substrate Review

Badlands uses existing datasets, emulation frameworks, detection-rule ecosystems, and defender workflows as anchors. No single substrate defines the environment. Each source constrains one abstraction and leaves gaps that Badlands must model explicitly.

| Source | URL | What it anchors | What it does not anchor | How Badlands will use it |
|---|---|---|---|---|
| *Building Better Environments for Autonomous Cyber Defence* | https://arxiv.org/abs/2604.08805 | Environment design taxonomy: virtualisation gap for network/host plus user/threat simulation; modelling gap for sequence, observation, action, and reward modelling. Emphasizes green agents, realistic monitoring-derived observations, concurrency/time modelling, and reward alignment with security plus normal operations. | Does not prescribe Badlands' mission workflow, schemas, scoring weights, or implementation. | Primary design spine and reviewer checklist. Every abstraction must be classified as virtualisation or modelling and justified against this framework. |
| NCSC, “Why cyber defenders need to be ready for frontier AI” | https://www.ncsc.gov.uk/blogs/why-cyber-defenders-need-to-be-ready-for-frontier-ai | Operational motivation: frontier AI lowers attack cost and increases speed/scale; test-time processing can improve attack progress; defenders retain advantage by shaping the battlefield, correlating telemetry, understanding intended behavior, and responding effectively. Warns that automated response can cause service disruption worse than the attack. | Does not provide a simulator, dataset, or benchmark specification. It is strategic guidance rather than an environment contract. | Justifies always-on measurement, telemetry quality, mission-harm penalties, and response blast-radius scoring. |
| DARPA OpTC dataset | https://github.com/FiveDirections/OpTC-data | Enterprise-scale endpoint telemetry from DARPA Transparent Computing work. Anchors process/file/network event shapes, endpoint telemetry volume, and adversarial-plus-benign trace style. | Does not provide Badlands' mission workflow, live interaction loop, or full defender action model. Data is historical and de-identified. | Calibrate EDR-like event schemas, endpoint background rates, and examples of adversarial artifacts. Prevents toy observations such as direct compromise labels. |
| LANL Comprehensive Multi-Source Cyber-Security Events | https://csr.lanl.gov/data/cyber1/ | 58 days of de-identified enterprise events from multiple sources. Anchors long-duration temporal rhythms, auth/network/event background rates, and multi-source correlation. | Does not include an interactive defender/attacker environment or mission-impact model. De-identification limits semantic detail. | Calibrate green event timing, log volume, delayed/noisy multi-source observations, and baseline anomaly rates. |
| LANL Unified Host and Network Dataset / user-computer authentication associations | https://csr.lanl.gov/data/ | Enterprise authentication and association structure. Anchors which users normally authenticate to which hosts and how identity graphs constrain plausible lateral movement/anomaly detection. | Does not define mission tasks, EDR process artifacts, or response actions. | Build realistic user-host affinity, privilege/credential spread, and suspicious-but-benign login baselines. |
| Mordor / OTRF Security Datasets | https://mordordatasets.com/ and https://github.com/OTRF/mordor | ATT&CK-mapped adversarial datasets and replayable detection scenarios. Anchors concrete attack telemetry, rule-testing workflows, and adversarial evidence examples. | Not a full active network with green mission users, defender action effects, or continuous timing. | Source examples for alert/telemetry artifacts, detection validation, and attack-chain trace templates. |
| MITRE CALDERA | https://caldera.mitre.org/ and https://github.com/mitre/caldera | Adversary emulation and automated response platform. Anchors executable attacker abilities, planner concepts, operational plugins, and concrete action side effects. | CALDERA is not itself the Badlands scoring environment and does not solve green mission modelling or reward design. | Calibrate attacker action prerequisites, durations, artifacts, and later higher-fidelity replay for selected chains. |
| MITRE ATT&CK | https://attack.mitre.org/ | Shared taxonomy for adversary tactics, techniques, and procedures. Anchors labels on attacker actions and detections. | ATT&CK is not an event schema, timing model, or environment validity guarantee. | Tag red actions, alerts, and evaluation slices without mistaking taxonomy coverage for realism. |
| Cyberwheel | https://github.com/ORNL/cyberwheel | High-fidelity ACD simulator/emulator direction with attention to realistic monitoring and network/host state. Anchors the aspiration for simulator-to-emulator validation and practical observation pipelines. | Badlands must still define its own mission workflow, scoring, and trace contract. | Reference design for active environment construction and for avoiding magic observations. Compare Badlands design choices against Cyberwheel patterns. |
| CybORG | https://github.com/cage-challenge/CybORG | Common autonomous cyber-defense benchmark and baseline environment. Anchors comparison to established ACD tasks and known pitfalls. | Earlier CybORG-style abstractions have documented modelling limitations; it does not by itself prove Badlands validity. | Use as a baseline/reference point, not as the target abstraction. Badlands should explicitly state where it differs on observations, green activity, and timing. |
| NASimEmu | https://github.com/dfki-in-sec/NASimEmu | Sim-to-emulation transfer for network attack simulation. Anchors the idea that abstract actions should be validated against emulated execution. | Focuses primarily on attack-side network simulation/emulation rather than full defender/green mission scoring. | Inform later validation of red action success probabilities, durations, and artifacts against emulation. |
| Elastic Common Schema (ECS) | https://www.elastic.co/guide/en/ecs/current/index.html | Production-style normalized event fields for endpoint, network, process, file, DNS, and authentication data. | ECS is a schema, not a simulator, detection policy, or mission model. | Define defender-facing log fields and ensure observations look like realistic SIEM/EDR data. |
| Elastic detection-rules | https://github.com/elastic/detection-rules | Production-style detection rule metadata, severity/risk, query logic, ATT&CK tags, and false-positive notes. | Rule hits are not ground truth and do not define action effects or scoring. | Shape alert objects with source events, rule provenance, severity/confidence, and known false-positive context. |
| Sigma | https://sigmahq.io/ and https://github.com/SigmaHQ/sigma | Vendor-agnostic detection rule format and detection engineering workflow. | Sigma rules do not guarantee detection quality and do not model environment dynamics. | Provide optional rule-style references for alert generation and detection provenance. |
| Real SOC/EDR/SIEM/ticket workflows | NIST incident response guide: https://csrc.nist.gov/publications/detail/sp/800-61/rev-2/final ; CISA incident response resources: https://www.cisa.gov/resources-tools/resources/incident-response-playbook | Defender workflow: triage, investigation, containment, eradication, recovery, escalation, evidence review, rollback, and communication. Anchors analyst time and operational blast radius. | General guidance does not provide exact event distributions or automated-agent interfaces. | Define defender action set, durations, case/ticket artifacts, and harmful-defense scoring. |

## Design implications

1. **Observations must be artifacts.** ECS/Sigma/Elastic/OpTC/LANL anchor logs and alerts; no defender receives hidden truth.
2. **Green is mandatory.** The anchor paper and NCSC guidance both imply that defense without operational continuity is not mission-relevant.
3. **Time must matter.** Sequence modelling, logging delay, action duration, and overlapping attacker/defender/user activity are part of the environment contract.
4. **Scoring must punish bad defense.** NCSC's warning about harmful automated mitigation becomes explicit mission-disruption and false-positive scoring.
5. **Emulation is validation, not the first product.** CALDERA/NASimEmu/Cyberwheel guide higher-fidelity checks after the contract is stable.
