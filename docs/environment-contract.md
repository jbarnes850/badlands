# Environment Contract: Mission Desk Enclave

This contract defines what an implementation must satisfy before Badlands can claim construct-valid environment measurement.

The current Mission Desk world inventory and cadence are defined in
`badlands/scenarios/mission_desk.json`; see
[`docs/scenario-fixtures.md`](scenario-fixtures.md) for the scenario schema and
provenance contract.

## Hidden simulator state

Hidden state is owned by the active network and is never emitted directly to agents.

### Assets and topology

- `host_id`, role, owner, OS/service inventory, patch posture, criticality.
- Network segment and allowed flows.
- Service health for identity provider, mission app, file share, email, ticketing, SIEM/EDR collectors.
- Mission dependency graph: which services/hosts support each mission task.

### Identity and credentials

- Users, groups, privileges, service accounts.
- Active sessions and tokens.
- Credential material location and exposure state.
- MFA, reset, disabled, and lockout state.

The first implemented identity slice is specified in
[`docs/identity-service-contract.md`](identity-service-contract.md). Login,
session validation, reset/lockout, and credential-use outcomes are authoritative
in the local IdP service; simulator state may only mirror service evidence.

### Files, processes, and services

- File existence, sensitivity, access control, modification history.
- Process trees, command lines, parent/child relationships, network connections.
- Persistence mechanisms and scheduled tasks.

The current mission app, file-share, and ticket authority boundary is specified
in [`docs/mission-service-contract.md`](mission-service-contract.md). Mission
task completion/failure, file reads, and ticket creation/update are service
state transitions with trace-ingested service telemetry; Python may schedule
work and mirror observed service outcomes but must not silently replace service
truth.

### Attacker state

- Footholds, privileges, known credentials, discovered topology, persistence, in-flight actions.
- Objective progress: collection, exfiltration, disruption, lateral movement.
- Noise generated by attacker operations.

### Defender state

- Open alerts/cases, analyst time budget, pending investigations, action cooldowns.
- Containment rules, isolated hosts, reset users, blocked indicators, rollback state.

### Green/mission state

- User schedules, task queues, deadlines, productivity, ticket backlog.
- Active user sessions and application/file usage.

### Telemetry state

- Raw event buffers, normalized event buffers, detection queues.
- Sensor coverage, drop rates, clock skew, event delay, alert delay, false positive processes.

## Observation surfaces

### Defender observations

Allowed surfaces:

- SIEM alerts: rule id, severity, confidence, source event ids, timestamp, affected assets/users, ATT&CK tags when available, known false-positive notes.
- ECS-like normalized endpoint events: process, file, registry/config, network connection, DNS, auth, service events.
- EDR views: process tree, hash/path/user, parent process, first/last seen, containment status.
- Identity/auth logs: login success/failure, source/destination, privilege changes, token resets, anomalous user-computer pairs.
- Network summaries: flows, DNS queries, blocked/allowed traffic, beacon-like patterns when detection rules fire.
- Email/ticket artifacts: phishing reports, user complaints, outage reports, SOC case notes.
- Asset inventory: host role, owner, criticality, service dependencies, patch posture.
- Delayed action results: success, failure, partial success, blast-radius indicators.

Forbidden surfaces:

- `host_compromised`, `attacker_location`, `credential_stolen`, hidden attacker objective state, future green schedule, scoring fields.

### Attacker observations

Allowed surfaces:

- Shell/tool output for commands actually executed.
- Service banners and scan results subject to network reachability and timing.
- Accessible file listings/content subject to permissions.
- Credentials or tokens actually discovered.
- Error messages, timeouts, blocked connections, account lockouts.
- Effects of defender actions only as experienced by attacker tools.

Forbidden surfaces:

- Defender alerts/cases unless explicitly exfiltrated, green schedules, hidden topology, scoring fields.

### Green observations

Allowed surfaces:

- Application success/failure, latency, file availability.
- Account lockout/reset prompts, host isolation notices, blocked email/network access.
- Ticket responses and mission task status.

Forbidden surfaces:

- Attack truth, SOC internal state, hidden scoring fields.

## Action surfaces

All actions have prerequisites, start time, duration, completion event, side effects, and observable artifacts.

### Defender actions

- `triage_alert(alert_id)`: 2-6 min; creates case note and linked evidence view.
- `query_endpoint(host_id, window)`: 1-4 min plus logging delay; returns EDR/process/file/network slice.
- `query_identity(user_id|host_id, window)`: 1-4 min; returns auth/session history.
- `query_network(indicator|host_id, window)`: 1-4 min; returns DNS/flow summaries.
- `isolate_host(host_id)`: 1-3 min; blocks most network flows; mission impact if host/service is needed.
- `reset_account(user_id)`: 2-5 min; revokes sessions; mission impact if active benign work exists.
- `block_indicator(type, value, scope)`: 1-5 min; may block benign dependencies.
- `kill_process(host_id, process_ref)`: 1-3 min; may fail or kill benign work.
- `restore_host_or_service(target)`: 5-20 min; repairs availability after containment/disruption.
- `escalate(case_id)`: 5-15 min; increases evidence quality/action authority at analyst-time cost.
- `rollback(action_id)`: 2-10 min; reverses some harmful defensive effects.

### Attacker actions

- `discover_local(host)`: 1-5 min; emits process/file/auth artifacts.
- `scan_network(scope)`: 2-10 min; emits network/DNS/EDR artifacts depending stealth.
- `attempt_credential_access(host|file|process)`: 3-15 min; may expose credential or trigger alert.
- `establish_persistence(host)`: 3-10 min; creates process/file/service artifacts.
- `lateral_move(src, dst, credential)`: 2-10 min; success depends on credential, reachability, defense timing.
- `collect(target)`: 5-20 min; reads sensitive files or app data.
- `exfiltrate(channel, bundle)`: 5-30 min; creates network artifacts and mission/security impact.
- `disrupt_service(target)`: 2-15 min; degrades mission app/file/identity service.

### Green actions

- `login(user, host)`: seconds-2 min; emits auth event.
- `use_mission_app(task)`: 1-10 min; requires identity, app, and dependencies.
- `read_write_file(task)`: 1-8 min; requires file share and permissions.
- `send_email(message)`: seconds-2 min; may include phishing report or benign attachment.
- `create_ticket(issue)`: 1-5 min; emits ticket artifact.
- `run_benign_script(host)`: 1-10 min; may resemble suspicious process behavior.

## Event model

Every run writes an append-only trace. Required event classes:

- `action_requested`: agent, action type, parameters visible to environment, request time.
- `action_started`: accepted action, precondition result, start time, planned duration.
- `action_completed`: success/failure/partial, completion time, side effects, generated artifact ids.
- `state_transition`: hidden state change reference; not agent-visible but trace-visible for audit.
- `telemetry_emitted`: raw event id, source, normalized fields, visibility delay.
- `alert_emitted`: rule id, source event ids, severity, confidence, delay, false-positive metadata if known to scorer.
- `observation_delivered`: agent, observation ids, delivery time.
- `mission_task_event`: task started/completed/failed/delayed, user, dependency.
- `defense_harm_event`: lockout, isolation, blocked dependency, killed benign process, outage.
- `security_impact_event`: persistence active, credential spread, lateral movement, collection, exfiltration, disruption.
- `score_snapshot`: derived fields at scoring interval with source event references.

Trace requirements:

- Events are timestamped on the environment clock.
- Events have stable ids and parent/source event references.
- Agent observations reference event/artifact ids rather than hidden state.
- Scores reference trace evidence sufficient for replay.
- Hidden state transitions may be logged for audit, but must be excluded from agent observations.

## Timing model

Badlands uses an event-driven clock. Actions are not instantaneous unless explicitly modelled as sub-second. The environment maintains a priority queue of in-flight actions and scheduled green/telemetry/detection events. Attacker, defender, and green effects can overlap.

Race examples that must be representable:

- Defender resets an account while attacker lateral movement using that token is in flight.
- Host isolation cuts off exfiltration but also prevents a mission analyst from submitting a deadline task.
- Logging delay causes an alert to arrive after attacker persistence is established.
- Benign admin script and attacker discovery produce similar process telemetry.

## Scoring fields derived from trace

- `mission_tasks_completed`, `mission_tasks_failed`, `deadline_minutes_lost`.
- `service_downtime_minutes` by service and criticality.
- `user_lockout_minutes`, `host_isolation_minutes`, `benign_process_kills`.
- `attacker_dwell_minutes`, `persistence_minutes`, `credentials_compromised_count`.
- `lateral_movement_count`, `sensitive_files_accessed_count`, `exfiltration_bytes_or_units`.
- `time_to_first_alert`, `time_to_triage`, `time_to_containment`.
- `true_positive_actions`, `false_positive_actions`, `unnecessary_blast_radius`.
- `analyst_minutes`, `action_count`, `escalation_count`.
- `overall_security_score`, `overall_mission_score`, `overall_defense_quality_score`.

Scores must be recomputable from `action_*`, `telemetry_*`, `alert_*`, `mission_task_event`, `defense_harm_event`, and `security_impact_event` records.
